# 여행의 사이

국내·해외 여행을 두 사람이 함께 계획하는 한국어 웹앱입니다. 실제 여행은 빈 상태에서 시작하고, 샘플은 사용자가 선택할 때만 생성됩니다.

## 지금 사용할 저장 방식

현재 설정은 **Supabase Auth + Supabase 클라우드 DB**입니다. 기존 포폴분석의 Supabase 프로젝트 설정을 여행 전용 .env로 연결했습니다. 실제 프로젝트의 응답과 여행 테이블 준비가 확인되어야 가입·저장이 동작하며, 연결 실패 시 로컬 저장으로 전환하지 않습니다.

**처음 설정과 사용 순서는 [SUPABASE-사용법.md](./SUPABASE-사용법.md)를 보세요.** 실행 중인 앱의 http://localhost:4310/setup.html 에서도 안내와 SQL 복사 버튼을 제공합니다.

## 실행

Node.js 24.x가 필요합니다. 이 컴퓨터에는 의존성 설치를 마쳤습니다.

1. 여행 폴더의 실행.cmd를 실행하거나 터미널에서 npm start를 실행합니다.
2. http://localhost:4310/setup.html 에서 연결 상태와 설정 절차를 확인합니다.
3. 준비 완료 후 http://localhost:4310 에서 회원가입 → 이메일 인증 → 로그인합니다.

새 컴퓨터에서는 npm ci를 먼저 실행합니다. Windows 인증서 문제는 NODE_USE_SYSTEM_CA=1 또는 Node의 --use-system-ca로 시스템 인증서를 사용하세요. 인증서 검증을 끄지 마세요.

## 핵심 기능

- 여행 생성·수정·삭제, 예정/지난 여행, 국내·해외 목적지·기간·동행·이미지 URL·메모·관심사·예산.
- Supabase 이메일 로그인과 HttpOnly 세션 쿠키, 비공개 여행, 7일·1회 사용 2인 초대, 취소·참여 해제.
- 장소 저장자, 하트, 둘 다 좋아하는 장소 필터, 댓글, 카테고리 필터, 중복 장소 안내.
- 날짜별 일정, 시간순 정렬·수동 순서 변경·날짜 이동, 저장 장소 연결, 기간 밖 일정 보존.
- Leaflet 지도, 방문 순서 핀과 선택 연동, 직선거리, Google Maps 길찾기, 국내 네이버 지도.
- 여러 숙소의 후보/예약 완료/취소, 체크인·아웃, 비용·거리 비교, 날짜별 출발·도착지 연결.
- 교통편·기타 예약, 담당자를 지정하는 준비물·할 일 체크리스트.
- 입력 환율, 예상·실제 비용, 날짜·분류별 합계, 결제자별 정산, 연결 지출 중복 방지.
- 하트·관심사·숙소 거리·일수별 예산을 참고하는 저장 장소 기반 코스 제안. 외부 AI 추천은 미연결입니다.
- JSON 내보내기·새 여행으로 가져오기. 공유 권한은 복사하지 않고 작성자·결제자는 가져오는 계정으로 설정하며 댓글·하트는 초기화합니다.
- 모바일 일정/지도 전환, 빈 상태, 저장·재시도 안내, 충돌 시 최신 내용을 비교한 후 입력을 유지해 재저장.

## 공유와 배포

두 사람은 같은 앱 주소에서 각자 가입하고 초대를 수락합니다. Supabase 모드에서는 약 2초 간격으로 DB의 버전·참여 권한을 확인하며 변경을 자동 반영합니다. 세션은 주기적으로 Supabase Auth로 다시 확인합니다.

localhost는 현재 PC의 주소입니다. 같은 Wi-Fi의 휴대폰은 PC의 LAN 주소를 사용하고, PC와 서버가 켜져 있어야 합니다. 휴대폰 접속·방화벽 통과는 실제 기기로 검증하지 않았습니다.

**인터넷 공개 배포는 아직 수행하지 않았습니다.** Vercel 배포용 API와 설정은 준비되어 있습니다. [Vercel 배포 방법](./VERCEL-배포방법.md)을 따라 진행할 수 있습니다. 집 밖에서도 사용하려면 Node 서버를 HTTPS로 배포하고 PUBLIC_URL, COOKIE_SECURE=true, Supabase Auth Redirect URLs를 해당 앱 주소에 맞춰 설정해야 합니다. Dockerfile을 제공합니다. Supabase 모드의 회원·여행 데이터는 로컬 디스크에 의존하지 않으며, Vercel 배포에서는 약 4초 간격으로 변경을 확인하므로 장시간 SSE 연결에 의존하지 않습니다.

## 지도·검색·비용 기준

API 키 없이 직접 등록·지도 클릭 좌표 선택·기본 지도·번호 핀·직선거리·외부 길찾기·저장 장소 기반 추천을 사용합니다. 지도 타일은 인터넷 연결이 필요합니다.

GEOAPIFY_API_KEY를 서버 .env에 설정하면 주소/장소 검색과 도보·자동차 경로 조회 코드가 활성화됩니다. 실제 키가 없어 이 외부 서비스의 성공 응답은 검증하지 않았습니다. 일본·국내 등 지역에 따라 검색·경로 가용성이 다릅니다. 대중교통 시간표는 외부 길찾기로 연결합니다. 경로를 조회한 구간만 실제 거리·시간 합계를 표시하며, 지도 점선은 항상 장소를 연결한 직선입니다.

링크 자동 정보 추출, 실시간 환율, 외부 평점·영업시간 수집, 예약 결제, 파일 업로드는 연결하지 않았습니다. 사진은 URL로 입력합니다.

예상 비용은 예약 완료 숙소 + 예약 + 숙소 이외 일정 비용입니다. 숙소는 일정에 반복되어도 한 번만 합산하고 후보·취소 숙소는 제외합니다. 실제 지출은 결제 완료 예약 + 지출 기록이며 원본 예약과 연결된 지출이 있으면 그 금액으로 대체합니다. 환율이 없는 외화는 원화 합계에서 제외하고 부분 합계·정산 미완성을 안내합니다. 결제자 외 1인 부담이 50%이면 반반, 0%이면 결제자가 전액 부담합니다.

## 데이터와 보안

비밀번호는 Supabase Auth가 관리합니다. 여행 전용 travel_profiles, travel_workspaces, travel_invites 테이블은 RLS와 직접 접근 권한 차단을 적용합니다. 서버가 로그인 사용자를 검증하고, DB 함수가 참여 권한·버전·초대 유효성을 다시 확인하며 원자적으로 저장합니다. service_role/secret 키는 서버에만 보관합니다.

기존 SQLite 파일은 그대로 보존합니다. STORAGE_BACKEND=sqlite를 명시하면 별도의 로컬 계정·저장소를 사용할 수 있습니다. 이 모드의 비밀번호는 scrypt+salt, 로그인·초대 코드는 해시로 저장합니다. 두 저장 모드의 계정과 세션은 서로 다릅니다. 기존 여행을 옮기는 절차는 Supabase 사용법 문서에 있습니다.

## 검증

- npm run check: 서버·도메인·브라우저 JS 문법 검사.
- npm test: SQLite HTTP 통합 테스트, 비용·기간·이동 검증, PostgreSQL(PGlite)에서 실제 SQL 함수·권한·초대·충돌 검사, Supabase Auth SDK 요청·쿠키·키 비노출·장애 처리의 모의 응답 테스트.
- npm run supabase:check: 실제 Supabase 연결·테이블·함수 준비 확인. 비밀 키와 사용자 데이터를 출력하지 않습니다.

실제 Supabase 프로젝트에서 가입 이메일·두 계정 저장·새로고침·공유까지 확인해야 실연결 검증이 완료됩니다. 자동 테스트는 실제 Supabase 계정이나 운영 데이터를 생성하지 않습니다.
