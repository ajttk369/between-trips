# 관리자 회원 관리

관리자 화면: `/admin.html`. 일반 회원 로그인과 별도의 관리자 세션을 사용합니다.

## 배포 설정

Vercel 프로젝트 → Settings → Environment Variables에서 `ADMIN_USERNAME`과 `ADMIN_PASSWORD`를 등록하고 다시 배포하세요. 로컬은 `.env`를 수정한 뒤 서버를 다시 시작합니다. 관리자 비밀번호가 설정되지 않은 배포에서는 회원 관리 API가 비활성화됩니다. 관리자 자격 증명은 브라우저 번들·Git·회원 테이블에 넣지 않습니다.

관리자 비밀번호는 추측하기 어려운 값으로 설정하세요. 관리자 세션은 30분이며, 비밀번호 환경변수를 변경하고 다시 배포하면 기존 관리자 세션도 무효화됩니다. 반복 로그인 실패를 제한하고 관리자 요청은 별도 HttpOnly·SameSite 쿠키와 같은 사이트 요청 검증을 사용합니다.

## 변경 가능한 항목

- 이름
- 로그인 아이디로 사용하는 이메일
- 회원의 새 비밀번호: 10~200자, 비워두면 기존 비밀번호 유지

기존 비밀번호는 조회하지 않습니다. 회원 고유 ID(UUID)는 여행·예약·공유 권한과 연결돼 있으므로 읽기 전용입니다. 수정 시 고유 ID와 여행 자료는 유지됩니다.

Supabase 모드에서는 `travel_profiles`에 등록된 여행 앱 회원만 조회·수정합니다. 같은 Supabase 프로젝트를 쓰더라도 여행 앱 사용 기록이 없는 다른 서비스의 계정은 관리 대상에서 제외합니다. 이메일 인증 전이고 아직 여행 프로필이 생성되지 않은 계정은 이 목록에 나오지 않습니다.

이메일·비밀번호는 Supabase Auth에 적용되므로 동일 Auth 계정을 사용하는 다른 앱의 로그인에도 영향을 줍니다. 이름은 Auth 메타데이터·여행 프로필·참여 중인 여행의 이름 표시에 반영합니다. 여행 이름 표시 갱신은 버전 검사로 동시 편집을 보호합니다. 인증 정보 저장 후 프로필 또는 여행 표시 갱신이 실패한 경우에는 일부 저장 상태를 오류로 알리며 다시 저장할 수 있습니다.

새 SQL 실행은 필요하지 않습니다. 운영 환경은 Supabase 서비스 역할 키를 기존 서버 환경변수로 사용하며 브라우저에는 노출하지 않습니다. 목록은 20명씩 표시하고 검색은 현재 페이지의 이름·이메일을 대상으로 합니다.
